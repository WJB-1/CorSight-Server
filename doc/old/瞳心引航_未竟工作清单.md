## 二、各模块详细实现状态

### 模块 1：街景数据库网络层 (Data Layer - Blind_map)

**技术栈**：Node.js + Express + MongoDB (2dsphere 索引)

| 子模块 | 状态 | 说明 |
|--------|------|------|
| 5.1 Overpass Proxy (OSM地图代理) | 已完成 | `/api/map/chunk` 接口实现完整，支持 bbox 查询、GeoJSON 转换 |
| 5.2 Data Receiver (数据上传) | 已完成 | `/api/upload/sampling_point` 支持 multipart 上传 8 方位图片 + JSON |
| 5.3 Spatial DB (空间数据库) | 已完成 | MongoDB 2dsphere 索引、采样点 Schema、DMS 坐标转换 |
| 5.4 Radius Search (半径查询) | 已完成 | `/api/navigation/nearby` 支持 lat/lon/radius 参数，Haversine 距离计算 |
| 健康检查端点 | 已完成 | `/health` 返回服务状态 |

**已实现接口**：
- `GET /api/map/chunk?bbox=` - OSM 行人路网查询
- `POST /api/upload/sampling_point` - 采样点上传
- `GET /api/navigation/nearby?lat=&lon=&radius=` - 附近采样点查询
- `GET /health` - 健康检查

**未竟工作**：
1. **接口 1.2：沿途特征批量查询** - `POST /api/db/points/route` 未实现
   - 契约要求：接收高德 API 途径坐标点串，返回沿途高危节点
   - 当前状态：完全缺失
   - 优先级：**高**（Agent 端行前预览需要）

2. **图片存储路径标准化** - 当前存储为 `/public/images/`，契约文档要求统一路径格式
   - 前后端兼容性说明中已指出 `syncService.ts` 的 `uploadSingleImage` 调用的是**未实现**的后端端点

3. **API 认证与限流** - 生产环境需要添加 API Key 认证和 Rate Limiting

4. **前端 uni-app 端云同步** - `Blind_map/frontend/` 目录存在但实现状态不明

## 五、技术债务与已知问题

### 当前技术债务

1. **前后端上传协议不一致**
   - 前端 `SyncService` 期望 `/api/upload/image` 单张上传
   - 后端仅实现 `/api/upload/sampling_point` 批量上传
   - 影响：uni-app 前端同步策略需要调整

2. **JSON 上传方式差异**
   - 前端 `uploadSamplingPointData` 使用 `application/json`
   - 后端使用 `multer` 解析 `multipart/form-data`
   - 影响：纯 JSON 请求无法被正确接收

3. **API Key 硬编码风险**
   - `voiceNavigation` 中百度语音 API Key 硬编码在 `strings.xml`
   - 高德 API Key 同样硬编码
   - 建议：迁移到服务端配置或加密存储

4. **LLM 降级响应过于简单**
   - 当前降级响应为固定模板
   - 建议：基于 IR 数据生成有意义的降级播报

5. **无单元测试覆盖**
   - 所有模块缺乏自动化测试
   - `navigation_agent/test/` 目录仅有手动调试脚本

### 已知限制（来自文档）

- TTS 需要网络（百度在线 TTS）
- 单路线选择（无多路线对比）
- 定位受高德 API Key 绑定限制
- 行前预览需独立部署后端

## 六、推荐开发顺序

### 第一阶段：行前预览闭环（1-2 周）

```
目标：让用户能从 Android App 发起预览请求并听到语音播报

1. 修复 TripPreviewService BASE_URL 配置
2. 后端添加 SSE 流式支持（或先使用轮询方案）
3. Android 端解析预览结果并接入 TTS 播报
4. 测试完整链路：语音输入 -> POI 选择 -> 预览请求 -> 语音播报
```

### 第二阶段：实时交互通道（2-3 周）

```
目标：实现行进中的实时环境问答

1. 后端实现 WebSocket 服务 (/agent/chat)
2. Android 端集成 WebSocket 客户端
3. 摄像头帧捕获与上传
4. VLM 视觉分析结果回调与 TTS 播报
5. 静默原则实现（仅震动/蜂鸣，不主动播报）
```

### 第三阶段：安全避障层（3-4 周）

```
目标：实现 0 延迟本地避障

1. 轻量化视觉模型选型（YOLOv8-nano / MobileNetV3）
2. TFLite 模型转换与量化
3. JNI 层开发
4. Android 端集成与威胁回调
5. 震动/蜂鸣静默告警机制
```

### 第四阶段：硬件延伸（4-6 周）

```
目标：解放双手的第一人称视角

1. ESP32-CAM 固件开发
2. Wi-Fi 配网与 MJPEG 流
3. BLE 设备管理集成
4. 硬件外壳设计与测试
```

## 八、总结

### 已实现的核心能力

- 街景数据库存储与空间查询（模块1）
- 多模型 LLM 编排与导航播报生成（模块3）
- Android 端语音导航基础功能（模块2 部分）
- 高德地图步行导航集成（模块2）

### 距离完整系统的差距

- **实时交互**：缺少 SSE 流式预览和 WebSocket 问答通道
- **安全避障**：边缘 AI 层完全未开始
- **硬件延伸**：IoT 采集设备未开始
- **接口对齐**：约 40% 的契约接口未实现或不对齐
